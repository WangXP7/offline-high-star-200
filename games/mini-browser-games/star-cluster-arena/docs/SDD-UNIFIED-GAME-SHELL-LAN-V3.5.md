# 星团大作战 v3.5 统一游戏外壳、帧率与局域网稳定性 SDD

## 1. 文档状态

- 版本：3.5.0
- 状态：自动化与本机封装验收通过；等待两台物理电脑互换房主复验
- 范围：Windows 桌面封装版、前后端网页版；不修改历史单 HTML 版本
- 目标：让单人和联机从同一个游戏首页进入、共用显示设置与资源目录，并修复“高图形帧率但联机仍像 60 帧以下”和局域网单向可连问题

## 2. 已验证现状与根因

### 2.1 帧率不是显卡没有被调用

桌面 v3.4 实测单人约 120 FPS、联机约 134 FPS，Electron 已请求高性能 GPU。5070 Ti/5060 不是瓶颈。联机体感不同来自三个时钟：

1. 单人物理固定 60 Hz；
2. 联机服务器权威模拟与快照仅 20 Hz；
3. 联机客户端虽然按显示器 `requestAnimationFrame` 绘制，但输入只以 30 Hz 上报。

因此“联机画面 FPS 高”不等于“权威状态更新快”。v3.5 将客户端图形帧率做成统一设置，把服务器权威模拟提升到 30 Hz、输入提升到 60 Hz，并在 HUD 中分别显示“图形 FPS / 权威 Hz”。30 Hz 是当前百人房的延迟、CPU 与带宽折中；本版本不把百人快照提高到 60 Hz，以免每个客户端带宽放大约三倍。

### 2.2 单机与联机不是同一个运行时

当前已经共用 `gameplay-core`、模式目录、外观目录与主要规则常量，但仍有两个会话循环和两个绘制器：单机由本地权威模拟驱动，联机由服务器权威快照驱动。这不是同一个模式简单加网络开关，所以玩家对视觉和手感不一致的判断成立。

最终架构不是强行让浏览器客户端同时运行服务器逻辑，而是：

```text
统一游戏首页 / 设置 / 资源 / 操作映射 / HUD
                    |
             统一客户端会话层
              /            \
   LocalAuthority 60 Hz   NetworkAuthority 30 Hz
      单机本地状态          快照 + 预测 + 校正
              \            /
          统一场景渲染与表现规则
```

v3.5 完成统一首页、统一设置、统一帧率节拍与统一诊断；现有共享规则继续作为唯一规则源。完整合并场景渲染器属于后续低风险迁移，迁移期间禁止重新实现一套玩法规则。

### 2.3 本机局域网单向连接的确定性根因

检查时发现 TCP `25555` 被旧的 `node backend/server.mjs` 进程占用，而且只监听 `127.0.0.1`；同一进程还占用 UDP `25556`。这会造成房主自己能打开、其他电脑无法访问，同时干扰房间发现。停止该已核验进程后，三个端口均已释放。

当前 Wi-Fi 为专用网络，当前 Electron/Node 路径已有专用网络 TCP/UDP 放行规则。系统中另有旧 v3.0 安装路径的阻止规则；它不会匹配当前 v3.4 可执行文件，但另一台电脑若存在指向当前程序路径的阻止规则，仍会导致单向失败。

v3.5 必须：

- 桌面应用只允许一个实例，第二次启动聚焦已有窗口；
- 内置服务始终监听 `0.0.0.0`，首选 25555，被占用时清楚显示实际备用端口；
- 诊断显示实际 TCP/UDP、可分享的局域网地址、防火墙状态和端口回退原因；
- 不自动删除或放宽用户防火墙规则；只提供诊断和系统设置入口；
- 退出房间必须立即发 `leave`，断线则按宽限期清理；退出桌面应用必须关闭内置服务。

## 3. 产品与 UI 设计

### 3.1 页面层级

1. 标题首页：单人游戏、局域网联机、设置、操作方式、关于、退出（仅桌面版）。
2. 单人大厅：模式、外观、商店、铁匠铺、成长；保留现有进度。
3. 联机大厅：创建/加入房间、房间列表、模式和自动补齐人数。
4. 对局：同一套快捷键语义与统一性能术语。

首页不在后台推进完整单人对局，避免玩家停在菜单时无意义占用 CPU/GPU。按钮使用原生可聚焦控件；Escape 返回上一级；设置表单有明确标签。

设计依据：Xbox 的游戏无障碍指南要求菜单可由键盘和数字输入完整导航，并建议提供重映射和灵敏度；Godot 的 UI 指南建议先分区、再用容器和边距构建可伸缩布局；Unity 文档要求在目标 Game View/分辨率中验证布局。

- https://learn.microsoft.com/en-us/xbox/accessibility/xbox-accessibility-guidelines/107
- https://docs.godotengine.org/en/3.2/getting_started/step_by_step/ui_main_menu.html
- https://docs.unity3d.com/kr/current/Manual/best-practice-guides/ui-toolkit-for-advanced-unity-developers/layouts.html

### 3.2 设置项

- 图形帧率：自动、60、90、120、144、165、240 FPS；自动匹配桌面传入的刷新率，上限 240。
- 画质：自动、性能、均衡、高；统一控制 DPR/像素预算。
- 显示性能信息：开/关。
- 联机缓冲：低延迟、均衡、稳定；分别使用更小/默认/更大的插值延迟。
- 屏幕震动：开/关。
- 设置存于 `localStorage`，单人和联机读取同一份结构；应用显示相关设置后重载当前页面。

不提供伪造的“解锁显卡性能”开关，也不声称网页能直接控制驱动 VSync。

## 4. 技术设计

### 4.1 共享设置模块

新增 `frontend/js/game-settings.js`，在单人和联机入口最先加载，提供：

- 版本化、白名单化的读写；
- 显示器刷新率解析；
- 目标 FPS 与渲染节拍；
- 画质对应的 DPR/像素预算；
- 联机缓冲预设；
- 设置变更事件。

### 4.2 更新频率

| 子系统 | v3.4 | v3.5 |
| --- | ---: | ---: |
| 单人物理 | 60 Hz | 60 Hz |
| 联机输入上报 | 30 Hz | 60 Hz |
| 联机服务器模拟 | 20 Hz | 30 Hz |
| 联机快照 | 20 Hz | 30 Hz |
| 单人/联机绘制 | 页面各自决定 | 共用设置，最高 240 FPS |

客户端插值、预测与校正必须继续使用服务器下发的 `serverHz`，不得写死 20/30。

### 4.3 兼容性

- 协议版本提升为 `sca-lan-v5`，旧客户端不能误入新房间；
- 房间模式和目标参与人数仍由共享目录定义；真人数量变化时 AI 自动补足到该模式目标人数；
- 外观继续从同一 `localStorage` 目录带入联机；
- 单 HTML 版不加载新模块、不参与兼容承诺。

## 5. 验收标准

### 5.1 功能

- 首次打开显示标题首页，不直接显示旧单人模式选择器；
- 单人、联机、设置、操作、关于均可从首页进入和返回；
- 桌面版显示退出按钮，普通网页隐藏；
- 设为 120/144/165 后，单人和联机调试状态均报告对应目标；
- 联机 HUD 同时显示图形 FPS 与权威 Hz；
- 任意模式真人加入后 AI 数量等于目标参与人数减真人数；
- 已选皮肤、孢子、光环、拖尾进入联机。

### 5.2 稳定性与性能

- `npm test`、`npm run check`、双实例 LAN harness 全通过；
- 百人目标模式 soak 在 30 Hz 下保持事件循环和带宽预算；
- 桌面单人和联机性能 smoke 通过；
- 1920×1080、1366×768 和窄屏下首页无溢出，键盘可访问；
- 首选端口被占用时桌面版使用备用端口，UI 明确显示实际地址；第二次启动不创建第二个服务器。

### 5.3 双机人工矩阵

同一 Wi-Fi 下对调房主角色各一次，覆盖创建、发现、房间码加入、准备、开始、退出、重进。若只有一个方向失败，先比较两台主机的监听地址、实际端口、网络配置文件和“当前 exe 路径”的防火墙阻止规则，不以显卡或百兆带宽作为首要假设。

## 6. 发布流程

1. 更新协议、服务端与共享设置。
2. 完成统一首页和两端帧率接入。
3. 运行静态检查、单元/集成/soak、浏览器视觉回归、桌面性能 smoke。
4. 版本提升至 3.5.0，重建安装程序与便携版。
5. 成品放入独立目录 `D:/GameTest/star-cluster-arena-desktop`，不放进仓库 `output`。
6. 双机人工矩阵通过后，再由用户决定是否推送开源仓库。
