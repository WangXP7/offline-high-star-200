# 星团大作战：单机玩法内核联机化重构 SDD v3.8

## 1. 文档状态

- 日期：2026-08-26
- 状态：纠偏实施中；服务器玩法已切换为单机源码，统一渲染器和实体双机验收未完成
- 产品基线：现有单机十模式的规则、节奏和表现
- 废止基线：`backend/multiplayer/simulation-v2.mjs` 不再作为可继续扩展的玩法实现
- 发布约束：在十模式一致性和双机体验验收全部通过前，不发布新的稳定版或宣称“联机已复刻单机”

## 2. 纠偏结论

用户关于“联机像另一个游戏”的判断成立。当前项目只共享了模式目录、外观目录和少量公式，并未共享完整玩法执行层：

```text
单机：frontend/js/game.js                  约 7300 行完整规则、AI、事件、地图和表现
联机：backend/multiplayer/simulation-v2.mjs 约 1500 行独立权威模拟
```

二者分别创建实体、更新 AI、处理模式目标和判定碰撞。继续在联机模拟器里逐条补规则，会长期产生两套游戏和新的漂移；本 SDD 禁止这种路线。

## 3. 重构前已证实差异

| 子系统 | 单机基线 | 当前联机 | 结论 |
| --- | --- | --- | --- |
| 完整执行循环 | `game.js` 的 `update` 及其完整阶段 | `simulation-v2.mjs` 的 `step` | 两套实现 |
| AI | 团队协作、救援、喂球、炸刺、魔王/魔兵专项决策 | 威胁、猎物、最近食点的简化决策 | 玩法明显不同 |
| 随机事件 | 23 个事件及完整倍率/实体效果 | 3 个精简轮换事件 | 闪电模式失去节奏与特色 |
| 安全区 | 多阶段移动、收缩和阶段资源曲线 | 单次线性半径插值 | 大逃杀节奏不同 |
| 魔王碰刺 | 走单机通用刺球碰撞和分裂逻辑 | 代码显式跳过 `role === "boss"` | 用户反馈可稳定复现 |
| 地图/小地图 | 单机绘制完整小地图、边界、毒圈、据点、刺球和玩家 | 联机对局没有同等小地图 | 表现缺失 |
| 模式技能 | 霸屏快合、冲刺种刺、完整冷却和事件倍率 | 独立简化技能 | 数值和反馈不同 |
| 资源与成长节奏 | 单机按模式、阶段、事件和 AI 行为共同形成 | 服务端独立资源与 AI 曲线 | 自动化“数值有限”不能证明好玩 |
| 外观数据 | 单机本地存档和完整绘制 | 共享目录但独立联机绘制 | 目录相同不等于表现一致 |

旧测试主要验证“不崩溃、值有限、网络包有界”，不能证明同一玩法。旧文档中把部分公式共享表述为“共享玩法内核完成”属于过度结论。

## 4. 唯一目标架构

```text
                          CanonicalEngine
          创建世界 / AI / 碰撞 / 事件 / 模式 / 结算 / 可序列化状态
                              |
                 +------------+------------+
                 |                         |
          LocalAuthority             NetworkAuthority
       浏览器固定 60 Hz 步进        房主服务固定 60 Hz 步进
       1 真人 + 自动补位 AI         2~8 真人 + 自动补位 AI
                 |                         |
                 +------------+------------+
                              |
                        ArenaRenderer
           世界、细胞、刺球、特效、小地图、模式 HUD 共用
                              |
                 本地状态 / 网络快照状态两种数据源
```

### 4.1 CanonicalEngine

`CanonicalEngine` 必须满足：

- 无 DOM、Canvas、WebSocket、Electron 和本地存档依赖；
- 使用可注入的确定性随机数，不直接调用 `Math.random()`；
- 所有时间规则使用秒和固定 `dt`，不依赖渲染帧数；
- 同一实例同时支持真人和 AI，联机真人只替换相同参与者槽位，不创建另一套角色规则；
- 状态可完整序列化，实体 ID、事件序号和随机数状态可恢复；
- 单机和服务器只能导入这个实现，不得保留同名替代逻辑。

最小接口：

```js
const match = new CanonicalEngine({ mode, participants, seed, startedAt });
match.setInput(participantId, input);
match.step(1 / 60);
const state = match.snapshot({ viewerId });
const events = match.eventsSince(lastEventSequence);
```

### 4.2 会话适配器

允许不同的只有状态来源和传输：

| 项目 | 单机 | 联机 |
| --- | --- | --- |
| 玩法步进 | 共享引擎 60 Hz | 同一个共享引擎 60 Hz |
| 真人槽位 | 1 | 2～8 |
| AI 数量 | 目标人数 - 1 | 目标人数 - 已连接真人 |
| 输入来源 | 键鼠/触控直接入队 | 校验后的网络输入入队 |
| 快照 | 直接读取引擎状态 | 20～30 Hz 编码发送 |
| 渲染 | 显示器刷新率，最高 240 FPS | 同一渲染器和帧率，远端插值、本地预测 |
| 暂停 | 可暂停权威步进 | 本地菜单不暂停房间权威步进 |

物理 60 Hz、网络快照 20～30 Hz、画面 60～240 FPS 是三个独立频率。联机不得因为网络快照较低而锁 60 FPS，也不得用渲染帧率改变玩法速度。

### 4.3 共用渲染器

- 删除单机 `draw*` 与联机 `draw*` 的双份场景实现；
- `ArenaRenderer.render(state, viewer)` 同时服务单机和联机；
- 小地图、世界边界、安全区、据点、病毒、吐球物、模式目标和外观都由同一渲染代码绘制；
- 联机专属代码只负责把快照缓冲转换成 `ArenaRenderer` 接受的标准状态；
- 特效由权威事件序号触发，不能靠客户端重新猜测碰撞结果。

### 4.4 当前过渡实现（2026-08-26）

为先停止错误的双玩法扩张，服务器生产入口已经从 `simulation-v2.mjs` 切换到 `canonical-single-runtime.mjs`。该适配器在 Node VM 中直接加载同一个 `frontend/js/game.js`，不是复制它的规则：

- 单机页面和服务器执行的源码标识均为 `frontend/js/game.js`；
- 服务器 60 Hz 固定步进，20 Hz 发送网络快照，客户端画面按设置独立刷新；
- 2～8 个真人替换相同参与者槽位，其余槽位继续使用单机 AI；
- 分裂、吐球、快合、冲刺、刺球碰撞、事件、安全区、据点、魔王和结算都调用单机原函数；
- 浏览器真实时间和刺球 `setTimeout` 已改为模拟时钟/模拟队列，保证服务器确定性；
- 生产代码不再导入 `simulation-v2.mjs`，该文件只作为失败版本的历史测试参照，后续删除。

这是一条“直接执行原单机源码”的纠偏桥，不是最终的无 DOM `CanonicalEngine`。Node 端当前用最小无界面 DOM 适配隔离单机 UI 调用；最终仍应按 4.1 把 UI 与规则自然拆开。联机对局画面目前仍由 `multiplayer.js` 绘制，已补回食点颜色、模式目标和小地图，但尚未满足“同一个 `ArenaRenderer`”的最终门禁，因此继续显示测试标签。

## 6. 迁移流程

### 阶段 A：冻结错误实现

1. `simulation-v2.mjs` 只允许读取用于协议兼容，不再新增玩法规则；
2. 首页和大厅保留“联机测试/重构中”标识；
3. v3.7.0-beta.2 标记为失败技术预览，不晋升正式版。

### 阶段 B：抽取单机基线

1. 把实体状态、创建世界、固定步进和确定性随机数抽到 `canonical-engine`；
2. 抽取基础碰撞、移动、分裂、合球、吐球、刺球和复活；
3. 让单机页面先改为调用引擎，画面和手感不得发生变化；
4. 每抽取一个阶段，就用旧单机黄金场景比对结果，禁止先改联机再回头猜单机规则。

### 阶段 C：抽取十模式插件

按依赖顺序迁移：自由 → 团队 → 生存 → 大逃杀 → 闪电 → 孢子 → 霸屏 → 据点 → 巨行星 → 魔王。每个模式必须同时迁移 AI、事件、技能、胜负和 HUD 数据，不做“只有数值表”的空迁移。

### 阶段 D：替换网络权威

1. 服务端房间实例直接创建 `CanonicalEngine`；
2. 删除服务器独立 AI、碰撞、事件、安全区和模式判定；
3. 网络层只做连接、房间、输入校验、固定步进调度、快照和重连；
4. 真人退出后同一个参与者槽位由引擎 AI 接管，房间结束后销毁实例。

当前进度：已通过直接单机源码适配完成 1～4；仍需把过渡 VM/无界面 DOM 适配收敛为 4.1 的纯规则模块。

### 阶段 E：共用画面

1. 抽取单机场景绘制为 `ArenaRenderer`；
2. 单机和联机都使用该渲染器；
3. 删除 `multiplayer.js` 中重复的细胞、刺球、外观和模式 HUD 绘制；
4. 联机大厅可以继续独立，但进入对局后必须走共用游戏场景。

当前进度：仅完成联机画面的食点颜色兼容、模式目标和小地图恢复；共享 `ArenaRenderer` 尚未完成。

## 7. 强制测试门禁

### 7.1 源码结构门禁

- 单机和服务端必须导入同一个 `CanonicalEngine` 构造器；
- 仓库检查禁止任何生产入口重新导入 `simulation-v2.mjs`；历史测试可以作为失败版本回归参照，但不得参与生产运行或提供联机结果；
- 单机和联机对局必须导入同一个 `ArenaRenderer`；
- 模式规则常量只能在共享引擎/模式插件中定义一次。

### 7.2 确定性黄金回放

每个模式至少包含：

- 固定种子、固定参与者、固定输入脚本；
- LocalAuthority 和 NetworkAuthority 连续运行完整目标时长；
- 每 60 tick 规范化序列化一次；
- 实体数量、质量、位置、AI 状态、事件、安全区、目标、排名和结果逐字段一致；
- 只允许快照压缩造成的明确量化误差，不允许规则误差。

### 7.3 行为场景

- 魔王、魔兵、AI、真人分别碰普通刺/大刺/孢子刺；
- 闪电基础移动、资源、事件间隔和制霸条件；
- 吐球喂刺、刺球发射、对远端玩家碰撞和拾取；
- 团队接球、救援、护航和禁止友伤；
- 大逃杀每个安全区阶段及圈外伤害；
- 霸屏快合、冲刺种刺、64 分身与覆盖率；
- 所有模式的小地图和模式 HUD 状态。

### 7.4 节奏回归

不再使用人为宽松的“数值有限”阈值。先从经用户认可的单机基线记录固定种子轨迹，再要求共享引擎满足相同轨迹：

- 每 10 秒总质量、领头质量、存活人数、击杀、食点和刺球数量；
- 首次分裂、首次击杀、首次事件、首次安全区阶段和结束时间；
- AI 目标类型和技能使用次数分布；
- 偏差超过明确容差即失败，不允许靠放宽阈值通过。

### 7.5 桌面与双机

- 逐帧白屏监测至少 5 分钟，窗口化和无边框全屏各一轮；
- WebGL 上下文丢失、GPU 子进程退出和 Canvas 后备缓冲重建进入日志；
- 两台电脑互换房主，十模式各跑一局；
- 渲染帧率按设置达到 60/120/144/160，权威物理保持 60 Hz，网络快照保持目标频率；
- 任何一台看到的小地图、事件、模式目标和结算必须一致。

### 7.6 当前自动化记录（2026-08-26）

- 全量测试 `159 / 159` 通过，包含双实例互相开房、主动退出、断线接管、真实 WebSocket 两人流程和十模式公开 API；
- 十模式各执行 1200 个 60 Hz 权威帧，目标总人数全部保留；物理步进 p95 为 `4.287～10.139 ms`，低于 `12 ms` 门禁；
- 孢子模式原先会让每个孢子逐一扫描所有刺球，464 个孢子时 p95 曾恶化到约 `45 ms`；现已在同一 `game.js` 内改为刺球空间网格候选查询，原碰撞公式和倒序判定不变，修复后同场景 p95 为 `6.736 ms`；
- 十模式 20 Hz 动态快照平均带宽为 `179.5～618.6 KiB/s`，低于 `2 MiB/s` 门禁；
- 窗口化连续 300 秒采集 9008 个合成帧，无边框全屏连续 300 秒采集 9014 个合成帧；两轮近白占比最大值均为 `0`，可疑帧、WebGL 上下文丢失和 Canvas 后备缓冲异常重建均为 `0`；
- RTX 5070 Ti / 160 Hz 桌面环境下，关闭逐帧白屏抓取时，闪电、魔王和霸屏联机自动化为约 `133～135 FPS`，服务器快照约 `20 Hz`；
- 设置页和首页按钮均已通过真实原生窗口切换：窗口化 → 无边框全屏 → 窗口化。

以上只代表本机自动化门禁。两台实体电脑互换房主并逐模式核对手感、画面与结算仍需人工完成，因此当前不创建正式 tag 或 Release。

## 8. 白屏专项

当前已排除页面自动重载、渲染进程崩溃、Windows 显卡重置和对局内周期 Canvas 尺寸重建。新增要求：

- WebGL 上下文丢失时立即隐藏失效图层，由深色 Canvas 2D 回退完整覆盖；
- 上下文恢复后先清为深色，再重新参与合成；
- Electron 记录 GPU/utility/renderer 子进程异常退出；
- 自动化订阅合成帧，超过 72% 近白像素或平均通道超过 220 立即失败；
- 若仍仅在实体机出现，必须用新增日志区分 WebGL 丢失、DWM 合成、窗口切换和页面导航，不再把“未复现”写成“已修复”。

## 10. 完成定义

只有同时满足以下条件，联机才可恢复为正式入口：

1. 十模式均由同一 `CanonicalEngine` 执行；
2. 单机和联机均由同一 `ArenaRenderer` 绘制对局；
3. 旧独立联机模拟器已删除；
4. 十模式黄金回放和行为场景全部通过；
5. 5 分钟白屏监测、长时 soak、双实例和实体双机十模式验收通过；
6. 安装版与便携版验证通过；
7. 用户确认模式特色、节奏和手感与单机基线一致；
8. 完成后才创建新版本 tag、GitHub Release 和桌面成品目录。
